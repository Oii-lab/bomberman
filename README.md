# 💣 Bomberman Online

兩人即時連線炸彈超人對戰遊戲。

🎮 **線上遊玩：** https://bomberman-online-1yh4.onrender.com

---

## 玩法

把網址傳給朋友，兩人輸入相同的房間 ID 即可開始對戰。

| 玩家 | 移動 | 放炸彈 |
|------|------|--------|
| 🔴 P1 | `WASD` | `Space` |
| 🔵 P2 | `↑↓←→` | `Enter` |

- 💣 炸彈 3 秒後爆炸，射程 2 格
- 🧱 橘色磚塊可被炸毀
- 🔥 被火焰波及即淘汰
- 連鎖爆炸、每局隨機地圖

## 連線原理

### WebSocket vs 傳統 HTTP

一般網頁的運作方式是「你問、伺服器答」，每次都要重新發一個請求。這種方式用在遊戲上會有明顯延遲，而且無法讓伺服器主動通知玩家。

WebSocket 則是在瀏覽器和伺服器之間建立一條**持續連線的雙向通道**，雙方都可以隨時主動傳送資料，不需要輪詢，適合需要即時同步的應用。

```
傳統 HTTP：
玩家A ──請求──▶ 伺服器
玩家A ◀──回應── 伺服器

WebSocket：
玩家A ◀──────▶ 伺服器 ◀──────▶ 玩家B
         持續連線              持續連線
```

### Socket.io

本專案使用 [Socket.io](https://socket.io) 實作 WebSocket 連線，它在原生 WebSocket 之上額外提供：

- 自動重連機制
- 若瀏覽器不支援 WebSocket，自動降級為 HTTP Long Polling
- 事件名稱（`move`、`bomb`、`state`...）讓程式碼更易讀

### 遊戲同步流程

遊戲採用**伺服器權威（Server Authoritative）**架構，所有遊戲邏輯都在伺服器計算，客戶端只負責顯示畫面和傳送輸入：

```
玩家A 按下 W 鍵
  │
  ▼
emit('move', 'up')  ──▶  伺服器收到
                          │
                          ├─ 檢查是否可移動
                          ├─ 更新玩家座標
                          └─ emit('state', 新狀態) ──▶ 廣播給房間內所有人
                                                          │
                                          玩家A 收到 ◀───┤
                                          玩家B 收到 ◀───┘
                                          重新繪製畫面
```

這樣設計的好處是兩個玩家的畫面永遠以伺服器為準，不會出現不同步的情況。

### 房間機制

伺服器用一個 `rooms` 物件管理所有對戰房間，每個房間最多容納 2 人。玩家進入時輸入相同的房間 ID，Socket.io 的 `room` 功能會確保廣播只發給同一房間的玩家，不影響其他對戰中的房間。

## 本地開發

```bash
npm install
npm start
# 開啟 http://localhost:3000
```

區網對戰：查詢自己的 IP，朋友連 `http://你的IP:3000`（需在同一 WiFi）
